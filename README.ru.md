# NovelForge — универсальный ИИ-инструмент для творчества

---

Крупный, полностью настраиваемый локальный ИИ-инструмент для творчества, объединяющий в едином каркасе способностей **написание романов** и **имитацию/продолжение/переписывание контента, написание резолюции Совбеза ООН, академическое письмо-обращение**, а также поддерживающий **многоязычное письмо**. Писательский конвейер: **идея-вдохновение → сюжетный маршрут → устройство мира → персонажи → план глав → текст глав**, и на каждом шаге результат работы ИИ можно **предпросмотреть, сохранить в проект, свободно отредактировать, перегенерировать, точечно доработать или полностью откатить (отмена)**; поддерживается подключение OpenAI-совместимых интерфейсов (включая отечественных поставщиков), Gemini, Grok/xAI; встроен **офлайн-симуляционный движок** и примеры романов — **для полноценного знакомства со всеми функциями не требуется ни один API Key**.

Ноль сторонних зависимостей (чистая стандартная библиотека Node.js + нативный браузер), все данные хранятся на вашем компьютере.

## Быстрый старт

Требования: Node.js ≥ 18.17 (рекомендуется 20+).

```bash
# Способ 1: прямой запуск
node server/index.js

# Способ 2: в Windows дважды щёлкните run.bat (браузер откроется автоматически)
```

После запуска **браузер открывается автоматически** по адресу http://127.0.0.1:7390 (установите переменную окружения `NOVEL_NO_OPEN=1`, чтобы отключить автозапуск; `NOVEL_PORT` меняет порт, `NOVEL_DATA` — каталог данных). Если появится сообщение, что порт занят, значит экземпляр уже запущен — просто откройте этот адрес.

### Управление службой (фоновый режим, Windows)

Если не хотите занимать окно на переднем плане, используйте `novel-ctl.bat`, чтобы запускать и останавливать службу как **фоновый процесс** (журнал пишется в `data/server.log`, PID запоминается в `data/server.pid`):

```bat
novel-ctl.bat          rem = status (по умолчанию)
novel-ctl.bat status   rem просмотр состояния/порта/PID
novel-ctl.bat start    rem запуск в фоне (без окна и без открытия браузера)
novel-ctl.bat stop     rem остановка службы
novel-ctl.bat restart  rem перезапуск
novel-ctl.bat start 7400   rem можно указать порт; или без порта читается NOVEL_PORT / settings
```

При первом запуске автоматически выполняется:
1. запись настроек по умолчанию (пресеты 12 поставщиков + 25 шаблонов промптов);
2. создание встроенного примера проекта «Пример · Письмо из туманного порта» (мистика и детектив: библиотека сеттинга / 6 карточек персонажей / план 2 томов по 10 глав / 2 главы с текстом-образцом / архив связности);
3. движок по умолчанию = офлайн-симуляционный движок → откройте «Настройки → Движок по умолчанию» и замените на свою реальную модель.

## Процесс творчества (семь этапов + экспорт)

| Этап | Что делать | Ключевые возможности |
|---|---|---|
| ① Идея-вдохновение | Название / одно предложение / фон / конфликт / тон | Мозговой штурм ИИ (8 кандидатов, принятие по одному), одно кнопкой — углубление в заявку проекта |
| ② Сюжетный маршрут (план и подход к структуре) | 2–5 кандидатов: общий подход / маршрут по этапам / нарастание основного конфликта / направление финала / компромиссы и риски | ИИ генерирует кандидатов + **выбор человека** (по номеру / собственный маршрут / принять рекомендацию ИИ); **только после выбора план будет строго следовать ему** — ключевой шаг против «расползания плана» |
| ③ Устройство мира | Общий обзор / железные правила / разделы сеттинга / глоссарий | ИИ генерирует весь набор, дополняет инкрементально, детализирует по секциям; железные правила автоматически внедряются в каждое письмо |
| ④ Персонажи | Все поля карточки персонажа | Генерация группы / добавление / ИИ-доработка отдельной карточки / **калибровка согласованности всей группы** (возраст, связи, перекрёстная проверка таймлайна) |
| ⑤ План глав | По томам, по главам: цель + биты + участники + точка зрения + объём | ИИ строит план всей книги (дуги томов, с внедрённым выбранным маршрутом), добавляет N глав, дорабатывает отдельные главы, ручное добавление/сортировка/перевод в том/перестановка |
| ⑥ Написание глав | Редактор текста | Потоковое написание/продолжение/полная переписка/шлифовка всего текста/локальная переработка выбранного фрагмента; автосохранение, подсчёт слов в реальном времени; **автоматическое написание серии без контроля** (дописывание всех оставшихся глав по плану) |
| ⑦ Проверка связности | Архив памяти + обзор предзнаменований + эталон стиля + проверка всего текста | Каждая глава автоматически архивируется как «резюме + факты + статус предзнаменований» и внедряется в дальнейшее письмо; финальная редакторская проверка ИИ (логика/таймлайн/конфликты сеттинга/OOC/стиль/языковые ошибки), отчёт попадает в архив, не загрязняя текст |
| Экспорт | Загрузка в один клик | `book.md` готовое произведение / `manuscript.md` полная творческая подложка (со сюжетным маршрутом) / `book.txt` чистый текст / `backup.json` резервная копия проекта |

> **Почему маршрут обязателен**: без ограничения маршрутом модель склонна колебаться в «теме, способе нарастания конфликта и направлении финала», и написанный план теряет фокус от начала к концу.
> Поэтому этот инструмент делает «сюжетный маршрут (план и подход к структуре)» **предварительным этапом** плана — даже у идеи в один абзац сначала должно быть несколько вариантов маршрута на выбор.
> Автоматический режим «⚡ Всё автоматически» тоже сначала добавляет этот шаг и берёт за основу маршрут, рекомендованный ИИ (когда человек на месте, выбор рекомендуется делать вручную).

На протяжении всего процесса доступны: **«Отмена» в верхней панели** (применения ИИ и структурные изменения можно откатывать по всему проекту, 60 шагов), индикатор прогресса конвейера слева, «Журнал выполнения» внизу справа, «Настройки» вверху справа.

### Автоматическое написание серии без контроля
После готовности плана (или в любой момент): в боковой панели «⚡ Всё автоматически» прогоняет от недостающего звена до полной рукописи; на странице письма «⚡ План → серия без контроля» дописывает все оставшиеся главы. Во время работы можно **приостановить / продолжить / остановить**; каждая глава автоматически: пишет текст → резюме → архивирует факты и статус предзнаменований → следующая глава.

## Подключение реальных моделей

Откройте **⚙ Настройки**:
1. **Поставщики моделей**: уже предустановлены OpenAI, DeepSeek, 通义千问(Qwen/DashScope), 智谱 GLM, Kimi(月之暗面), 讯飞星火, 豆包(火山方舟), SiliconFlow, Ollama (локально), Grok(xAI), Gemini, симуляционный движок.
2. Заполните **BaseURL / API Key** (можно оставить пустым, если нет Key или локальная конечная точка типа `ollama`); внутри поставщика можно добавлять/удалять **строки моделей** (ID модели / отображаемое имя / контекстное окно — окно используется для автоматической обрезки контекстного бюджета).
3. Нажмите **⛁ Проверить соединение** для проверки; **⇣ Получить список моделей** подтягивает список онлайн.
4. Любая **OpenAI-совместимая конечная точка**, не поддерживаемая встроенными пресетами: нажмите «＋ Свой поставщик OpenAI-совместимый», BaseURL заполните до `/v1`.
5. **Движок по умолчанию и параметры генерации**: поставщик/модель по умолчанию, температура, максимальное число выходных токенов, целевой объём главы.
6. В панели генерации каждого действия ИИ также можно временно переключить движок и температуру (действует только в рамках этой сессии).

### Адаптированные протоколы
- `kind: openai`: `POST {baseURL}/chat/completions` (OpenAI/DeepSeek/Qwen/GLM/Kimi/讯飞/豆包/SiliconFlow/Ollama/Grok и любые другие совместимые конечные точки), поддержка потокового SSE и автоматического повтора при 429
- `kind: gemini`: `generateContent` / `streamGenerateContent?alt=sse`
- `kind: mock`: локальный офлайн-симуляционный движок (без сети и без Key)

## Шаблоны промптов (настраиваются)

Настройки → **Библиотека шаблонов промптов**: 25 шаблонов, сгруппированных по этапам, можно редактировать онлайн System/User промпты (плейсхолдеры `{{ideaText}}`, `{{bibleText}}`, `{{charsText}}`, `{{curRowText}}`, `{{contText}}` и другие автоматически внедряются системой), изменения мгновенно применяются ко всей последующей генерации; есть кнопка «Сбросить всё к встроенным значениям». Спецификации вывода для JSON-подобных действий (чистый JSON, без блоков кода) и правила оформления для текстовых действий (чистый текст, запрет пояснений) добавляются системой автоматически.

## Данные и безопасность

- Все данные на вашем компьютере: `data/projects/*.json` (по одному файлу на книгу, содержит все творческие данные и историю), `data/settings.json` (поставщики и Key).
- Копирование проекта = снимок уровня файла; экспорт `backup.json` позволяет долгосрочное архивирование.
- По умолчанию служба слушает только `127.0.0.1` (в `data/settings.json` в `server.bind` можно поменять на `0.0.0.0`, открыв локальную сеть — берегите свои Key).
- Ключи модельных API хранятся в открытом виде в файле настроек на вашем компьютере — этот инструмент задуман как персональный локальный письменный стол, не разворачивайте его в недоверенном окружении.

## Связь с DSH-версией плагина (отдельные репозитории · единый источник движка)

Этот репозиторий — **единственный источник истины для писательского движка**, специализированный на одном: только инструмент творчества  идея→**сюжетный маршрут**→сеттинг→персонажи→план→текст.
DSH-версия плагина (`dsh-novel-forge`, отдельный репозиторий/каталог `../novel-forge-plugin`) отвечает за оркестрацию службы в экосистеме harness и за сессионные инструменты `novel_forge_*`; она **встраивает зеркало этого движка** (`app/server`, `app/public`),
синхронизируется зеркальным инструментом в одну сторону, чтобы предотвратить расхождение двух мест:

```sh
# выполнить в репозитории плагина:
node scripts/engine-mirror.mjs verify   # проверить, совпадает ли зеркало движка (проходит только при 0 расхождений)
node scripts/engine-mirror.mjs sync     # синхронизировать server/ public/ этого репозитория в app/ плагина и перепроверить
```

Договорённость: **изменения поведения движка делаются только в этом репозитории** (после правок запустить тесты → `sync` в репозитории плагина → три самопроверки плагина);
репозиторий плагина пишет только код стороны harness (index.js службы / tools.js / client UI) и не меняет содержимое `app/`.

## Частые вопросы

- **Ошибка «порт уже занят / EADDRINUSE»**: значит уже запущен один NovelForge — просто откройте http://127.0.0.1:7390; или используйте `set NOVEL_PORT=7400`, чтобы сменить порт и запустить второй экземпляр; в Windows можно завершить старый экземпляр через `netstat -ano | findstr :7390` + `taskkill /PID <PID> /F`.
- **Если прямо в cmd ввести `NOVEL_PORT=7400 node server/index.js` и получить «не является внутренней или внешней командой»**: это синтаксис Linux/macOS; в командной строке Windows сначала выполните `set NOVEL_PORT=7400`, затем `node server/index.js` (или просто дважды щёлкните `run.bat` — порт определится автоматически).
- **Хотите начать заново с чистыми данными**: остановите службу, удалите/переместите `data/`, после перезапуска всё будет заново (пример пересоздаётся автоматически).
- **Локальный Ollama**: сначала `ollama serve` и `ollama pull` модели; пресет уже указывает на `http://127.0.0.1:11434/v1`.
- **Вывод симуляционного движка с явными метками**: это нормальное уведомление — после подключения реальной модели начинается настоящее творчество.
- **Изменения в шаблоне промпта не сработали?**: шаблоны хранятся в настройках, объединяясь по ключу; изменения применяются немедленно; если что-то испорчено, можно сбросить всё одной кнопкой.
